# 作品案例

项目基本信息统一保存在 `src/data/projects.yaml`，案例正文位于 `src/content/cases/`，支持 Markdown 和 MDX。每个项目最多关联一个案例，文件名不决定公开地址。普通正文优先 Markdown，需要组件时使用 MDX。

## 写作与发布

1. 为新项目创建案例文件，填写已有项目 ID 与独立 slug；更新已有案例时编辑原文件。项目基本信息修改参见[项目配置](configuration.md#项目配置)。
2. 完成正文并保持 `draft: true`。仓库的 `navigation.md` 草稿提纲供参考，需要作者补充真实内容。
3. 准备发布时显式设置 `draft: false`，按[写作完成条件](#写作完成条件)检查关联与公开入口。

```yaml
---
projectId: CF-Workers-Navigation
slug: navigation
draft: true
toc: true
---
```

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `projectId` | 是 | — | 项目 YAML 中已有的 `id`，区分大小写 |
| `slug` | 是 | — | 稳定 URL 标识，只接受小写字母、数字和单连字符分隔 |
| `draft` | 否 | `true` | 草稿不生成详情页或卡片案例入口 |
| `toc` | 否 | `true` | 显示二级、三级标题目录；关闭后仍显示阅读进度 |

schema 严格拒绝未知字段。标题、摘要、年份、标签、封面与外链均取自关联项目，不在案例 frontmatter 重复维护。`page` 为项目分页保留值，不能作为案例 slug。包括草稿在内，重复 slug、重复项目关联或不存在的项目都会让构建失败。

重命名文件不会改变 URL，修改 slug 会改变 URL。项目 ID 改名时同步修改案例关联。

## 展示边界

发布后生成 `/projects/{slug}`，项目卡片标题在当前标签页进入案例；未发布案例时，标题仍在新标签页打开项目外链。查看项目与在线演示始终保留为外链。

案例页显示项目封面、正文、目录和阅读进度，并提供返回项目列表入口。封面规则参见[配置说明](configuration.md#封面)。案例不提供博客评论、博客标签链接或相邻文章，也不进入博客搜索、标签和文章列表。

## 写作完成条件

- frontmatter 字段有效，slug 唯一且未误改，关联项目存在且没有第二个案例；正文使用真实内容，本地链接与图片路径存在。
- 草稿不生成详情页或卡片案例入口；发布后检查 `/projects/{slug}`、卡片标题入口、返回列表与项目外链符合本文规则，标题、摘要、年份、标签与封面均来自关联项目。
- 按[自动检查与产物](development.md#自动检查与产物)选择验证范围。改变案例字段规则时，按[编码与文档](development.md#编码与文档)同步 schema、示例与文档；改变路由、组件或客户端行为时补读[项目架构](architecture.md)。
- 发布或调整正文展示时，完成对应[人工验收](development.md#人工验收)，交付时列明检查结果与待验收项。
