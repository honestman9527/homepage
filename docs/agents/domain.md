# Domain Docs

本仓库采用 single-context 布局。

## 探索代码库前

- 读取根目录 `GLOSSARY.md`。
- 阅读 `docs/adr/` 中与当前任务相关的 ADR。
- 文件不存在时直接继续；领域术语或决策明确后，由 `domain-modeling` 技能按需创建。

## 检索与读取

- 先用 `rg --files` 或 `rg -n` 定位路径、符号和章节，再读取相关范围。已读且未变化的文档、技能复用当前会话内容。
- 首次检索只输出路径、命中行或相关片段；批量调用按所有结果的总量控制预算，初始约 4,000 tokens。需要更多证据时缩小目标后扩展读取；出现截断先调整范围。
- MCP 结果优先选择 `structuredContent`，否则提取 `content` 文本；只输出需要的字段和片段，避免同时打印两种表示或整个响应对象。
- 长检查沿用验证工具保留完整日志，向对话输出结果摘要与失败定位；需要诊断时再读取对应日志片段。

## 文件布局

- `GLOSSARY.md`：整个仓库的领域术语。
- `docs/adr/NNNN-<topic>.md`：架构决策记录。

## 使用领域术语

Issue 标题、设计提案、调试假设和测试名称中的领域概念，使用词汇表定义的术语。

需要的概念尚未收录时，先检查项目是否已有对应术语；确有缺口时，记录为 `domain-modeling` 的后续输入。

## ADR 冲突

方案与现有 ADR 冲突时，明确指出 ADR 编号、冲突内容及重新讨论的理由。
